## Production implementation

`whole-song.py --section-aware` opts into measured section policy. Existing single-instruction default processing and native real-time DSP are retained. Japanese `全体の音圧を少し上げて` and `音を潰さず迫力を出して` (also `音を潰さずに迫力を出して`) explicitly select the policy on confirmed Stereo Out input. These are bounded local rules, not a semantic or machine-learning assistant.

The packaged, independently inventoried section executable measures the same input in aligned three-second windows. Active median +/-6 LU classifies relatively quiet/loud sections; invalid loudness includes silence and short windows and is not claimed to prove digital silence. All sections, including partial tails, plus the full-file peak estimate protect gain headroom. Source content and timing remain untouched. No time-varying or per-section normalization is introduced.

Global gain is bounded by the existing requested A/B/C loudness targets, the loudest valid section, conservative source peak/EQ headroom and existing -24..12dB limits. Loudness/punch requests additionally cap the boost at 0.5/1/1.5dB (not guaranteed when ceiling/section limits prevent it). Loudness explicitly aims at original LUFS +0.5/1/1.5, bounded by the user target; a contradictory quieter target or inability to increase safely rejects the request instead of attenuating silently. Such requests alone apply neutral EQ and disable compression; they are not silently replaced by another tonal instruction. Punch with other supported clauses disables compression. Section crest below 6dB also disables extra compression. Final output still requires independent FFmpeg True Peak/LUFS checks, zero clipping, aligned sections and <=1.5dB section-gain variation / maximum active section-crest loss. This is a conservative heuristic guard, not proof of sound quality or a time-domain compressor diagnosis. Excessive change fails the candidate without adopting it; the original remains intact.

1–8 explicit clauses separated by `、`, `そして`, semicolons or newline are fully validated before output creation. Known aliases natural piano / soft highs / clean lows enter existing measured plans. Multiple clauses compose parameter proposals on the same confirmed input in written order; intermediate audio is not re-rendered/re-analyzed between clauses. DSP order remains EQ -> linked compressor -> global gain -> offline peak protection. Mixed instruments, target/role mismatches, duplicate clauses, warm-piano/low-cut conflict and any unrecognized clause reject the entire request. Vocal-forward remains the existing measured level/presence suggestion on explicitly chosen input; mixed vocals are not separated and intelligibility is not measured. Offline midpoint/history wording stays rejected; a separate existing-candidate AU midpoint path is described below. Never guess a replacement processing intent.

The native whole-song reply displays the instruction order/target and active/invalid section summary. New requests use the existing whole-song UI, separate candidates, explicit approval/adopt, source identity, stale settings, Undo and save/reopen paths. Multi-clause/loudness/punch policies are offline whole-song functions. Existing live AU natural piano / soft highs / clean lows aliases enter the same measured rules. Live AU midpoint preview supports `AとBの中間にして`, `AとCの中間にして`, `BとCの中間にして` only on same-target, same-settings, still-valid measured pending candidates. It keeps the selected endpoints as A/C and puts the midpoint at B. Gain/EQ/threshold/knee/makeup in dB use arithmetic means; Hz/ms/Q use geometric means; ratio uses the mean reduction slope (harmonic ratio), then host quantization. Bypass and enabled-state differences reject interpolation. No current parameters change until the existing apply/approval safety-render path; compare, apply, Undo and state/history persistence are exercised on the actual AudioComponent in CI. Evidence records the endpoints and full resulting proposal. This is parameter interpolation, not proof that the sound is perceptually halfway. No AU parameter IDs, DSP, state format, runtime dependencies or stable package selection are changed. Offline LUFS gain, 5ms lookahead/100ms release and global True Peak correction remain absent from live AU and are not claimed to match it.
