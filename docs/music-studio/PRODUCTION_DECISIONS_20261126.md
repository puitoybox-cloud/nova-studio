# ティアの判断が必要な5項目

2026年11月26日（日本時間）。[PR #680の受入見直し](PRODUCTION_ACCEPTANCE_TRIAGE_20261126.md)と[確定方針](MACLESS_REQUIREMENTS_V1.md#確定した方針)に基づく。以下はノヴァの提案。採用にはティアの判断が必要。

| 要件 | 決める内容 | 選択肢 | 推奨 |
| --- | --- | --- | --- |
| MS14-A05 本人声生成 | 同意する単位、撤回後のモデルと生成済み音声の扱い | 作品単位または利用するたびに同意を記録。撤回後は生成物を一括削除、または所有者の確認まで利用を停止して履歴を保持 | 作品・用途・声モデルの版ごとに本人同意を記録。撤回で新規学習・生成を停止し、既存生成物を要確認にして新規書き出し対象から外す。公開済み素材の扱いは本人と個別合意する。録音から作るHarmony等は別経路で継続。 |
| MS17-A02 実モデル採譜 | 楽器別・単音／和音別の正式合格基準 | 4楽器をまとめて受入、または楽器と方式の組合せごとに受入 | ピアノ・歌声・ギター・ベースの組合せごとに、正解付きの未使用演奏で音高・発音位置・長さを測る。音符F1と手直し時間を併記し、閾値は評価表を見て決める。根拠が揃った組合せから公開する。 |
| MS17-A03 信頼度と比較修正 | 曖昧な音符をどこまで自動処理するか | 全音符を候補として表示、または低信頼度を自動除去 | 低信頼度を色とラベルで示し、候補から除去する判断はユーザーに残す。元音声との同期試聴で確認でき、手修正をやり直せる設計にする。 |
| MS17-A04 自動整理と保存 | クオンタイズ・重複除去などの既定値 | 自動整理を既定で適用、または差分レビュー後に採用 | 生の採譜結果を保持し、拍合わせ・短い候補の除去は選択式。差分承認後に別MIDIトラックとして保存し、再開後も元音声と両版を比較できるようにする。 |
| MS23-A04 クラウド同期 | 双方向同期の要否、衝突時の扱い、暗号化と鍵の復旧 | 現行の端末内保存とiCloud・SSDバックアップを継続、または双方向同期を追加 | 当面は確定済みの端末内保存とバックアップを優先。双方向同期を追加すると決めた場合は、オフライン時の両版保持とユーザーによる解決を基本にし、暗号化と鍵喪失時の復旧方法を先に決める。 |

MS17の3項目は同じ採譜機能の判断。採譜の正式合格率は、現行台帳からは確認できない。
